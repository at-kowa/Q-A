# 検証手順（情シス質問箱 v0.4）

開発（ブランチ `feat/qbox-v04`）が終わったあとに、本人が行う手順です。上から順に進めてください。

```
全体の流れ
■□□□□□□  1. プルリクエストを作る
■■□□□□□  2. データベースを作る（SQL を4本）
■■■□□□□  3. テスト用のアカウントを作る
■■■■□□□  4. マスタ・利用者・テストデータを入れる
■■■■■□□  5. 手元の PC で動かして確認する
■■■■■■□  6. main にマージして Vercel で公開する
■■■■■■■  7. 受け入れ基準で判定する
```

---

## 1. プルリクエストを作る

`■□□□□□□ 1/7`

1. Edge で https://github.com/at-kowa/Q-A を開きます。
2. 画面上部に「feat/qbox-v04 had recent pushes」と出ていれば「Compare & pull request」を押します。出ていなければ「Pull requests」→「New pull request」→ compare を `feat/qbox-v04` にします。
3. base が `main`、compare が `feat/qbox-v04` になっていることを確認し、タイトルと説明を書いて「Create pull request」を押します（説明の例は、Claude にお願いすれば作ります）。
4. **まだマージしません。** 手順5の確認が終わってからマージします。

## 2. データベースを作る

`■■□□□□□ 2/7`

supabase の管理画面でプロジェクト「at-kowa」を開き、「SQL Editor」→「+ New query」で、次のファイルの中身を**この順番で1本ずつ**貼り付けて「Run」を押します。

| 順番 | ファイル | 作るもの |
|---|---|---|
| 1 | `supabase/migrations/20261022000100_qbox_v04_foundation.sql` | 利用者・マスタ・設定値、権限を判定する関数 |
| 2 | `supabase/migrations/20261022000200_qbox_v04_tickets.sql` | 投稿・添付画像、画像の置き場所（Storage） |
| 3 | `supabase/migrations/20261022000300_qbox_v04_responses.sql` | コメント・回答・既読（未読バッジ） |
| 4 | `supabase/migrations/20261022000400_qbox_v04_faqs.sql` | FAQ |

- それぞれ「Success. No rows returned」と出れば成功です。
- エラーが出たら、そこで止めて、エラーの文面を Claude に貼り付けてください。
- 「This query has destructive operations」などの確認が出た場合も、内容を Claude に見せてから進めてください。

## 3. テスト用のアカウントを作る

`■■■□□□□ 3/7`

supabase の管理画面で「Authentication」→「Users」→「Add user」→「Create new user」を開き、次の5人分を作ります。

| メールアドレス | 役割 |
|---|---|
| `900001@qbox.example.com` | 一般1 |
| `900002@qbox.example.com` | 一般2 |
| `900101@qbox.example.com` | 情シス担当1 |
| `900102@qbox.example.com` | 情シス担当2 |
| `900201@qbox.example.com` | 管理者 |

- パスワードは仮のもので構いません（初回ログイン時に変更を求められます）。チャットやファイルには書かないでください。
- 「**Auto Confirm User**」にチェックを入れてください（入れないとログインできません）。

## 4. マスタ・利用者・テストデータを入れる

`■■■■□□□ 4/7`

SQL Editor で、次の順に実行します。

| 順番 | ファイル | 内容 |
|---|---|---|
| 1 | `supabase/seed/01_masters.sql` | 拠点・場所・カテゴリ（架空の名前） |
| 2 | `supabase/seed/02_users.sql` | 手順3のアカウントと結び付けた利用者。最後に一覧が出るので `linked` がすべて `true` か確認 |
| 3 | `supabase/seed/03_test_data.sql` | 投稿7件・回答・コメント・FAQ 6件（1回だけ実行） |

## 5. 手元の PC で動かして確認する

`■■■■■□□ 5/7`

1. `app/config.js` がなければ、`app/config.example.js` をコピーして作り、supabase の URL と anon キーを書きます（qbox-test で使っていたものがあれば、そのままで構いません）。
2. Cursor のターミナルで `git switch feat/qbox-v04` を実行して、ブランチを切り替えます。
3. 同じターミナルで `node scripts/serve.mjs` を実行し、Edge で http://localhost:5173 を開きます。
4. 社員番号 `900001` と仮のパスワードでログインし、パスワード変更の画面が出ることを確認します。
5. 7章の「受け入れ基準のチェック表」の **機能** と **安全性** を、上から確認します。
6. 確認が終わったら、ターミナルで Ctrl + C を押してサーバを止めます。

## 6. main にマージして Vercel で公開する

`■■■■■■□ 6/7`

1. 手順5で問題がなければ、GitHub のプルリクエストで「Merge pull request」を押します。
2. Vercel の管理画面で「Add New…」→「Project」→ GitHub の `at-kowa/Q-A` を「Import」します。
   - Framework Preset は「Other」のままで構いません（設定は `vercel.json` に書いてあります）。
   - 「Environment Variables」に、次の2つを登録します（値は supabase の管理画面からコピー）。

     | 名前 | 値 |
     |---|---|
     | `SUPABASE_URL` | `https://xxxx.supabase.co`（`/rest/v1` は付けない） |
     | `SUPABASE_ANON_KEY` | anon / publishable キー（**service_role・secret キーは不可**） |
3. 「Deploy」を押し、完了したら表示された URL を Edge で開いてログインできるか確認します。
4. 取り込めない・ビルドが失敗する場合は、画面の文面を Claude に見せてください。

> 公開 URL は、検証に協力する人以外には案内しないでください。データはログインしないと一切読めない作りですが、画面そのものは URL を知っていれば開けます。

## 7. 受け入れ基準で判定する

`■■■■■■■ 7/7`

次をすべて満たしたら「この構成で Claude Code を使ってアプリを作れる」と判定します。

### 機能

| No | 確認すること | 確認のしかた | 結果 |
|---|---|---|---|
| 1 | 各権限でログインし、必須の全画面を表示・操作できる（画像の添付・表示を含む） | 900001（一般）・900101（情シス）・900201（管理者）でログインし、ヘッダーのメニューをすべて開く。一般で画像付きの投稿をし、情シスで画像を拡大表示する | ☐ |
| 2 | 投稿→割り当て→コメント→回答→完了→FAQ公開を最後まで実行できる | 一般で投稿 → 情シスで「自分が担当する」→ 情シスがコメント → 一般が返信 → 情シスが回答して「完了にする」→「FAQ として公開する」→ 一般で FAQ に表示される | ☐ |
| 3 | 受付一覧を開いたまま別の利用者が投稿すると、新着として表示される | Edge のウィンドウを2つ（片方は InPrivate）開き、情シスで受付一覧を開いたまま、もう片方の一般で投稿する。60秒以内に「新着」の印とタブの件数が出る | ☐ |
| 4 | 未読バッジが増減する | 情シスが回答すると、一般のヘッダーの「未読」が増える。一般がその投稿を開くと減る | ☐ |
| 5 | Edge（PC）と iPad（縦・横）で画面が崩れない | PC の Edge と、iPad の Edge で主な画面を開く | ☐ |

### 安全性

| No | 確認すること | 確認のしかた | 結果 |
|---|---|---|---|
| 1 | 未ログインでどのデータ・画像も取得できない | ログアウトした状態で F12 →「コンソール」に下の1行を貼り付けて Enter。表示が `0` か「permission denied」なら合格（テーブル名を `qbox_comments`・`qbox_faqs` などに変えて同じように確認） | ☐ |
| 2 | 一般の利用者が他人の投稿・内部メモを取得できない | 900002 でログインし、900001 の投稿の URL（`#/my/番号`）を直接開いても表示されない。テストデータの「検査記録が保存できない」の内部メモが、900002 の画面に出ない | ☐ |
| 3 | `qbox_users` 未登録・無効のアカウントでは何も取得できない | Auth にだけアカウントを作った社員番号でログインすると「登録されていません」と出て入れない | ☐ |

安全性1 で貼り付ける1行（Edge が貼り付けを止めた場合は、表示に従って `allow pasting` と入力してから貼り付けます）：

```js
(await import("/js/supabase.js")).db.from("qbox_tickets").select("id").then((r) => console.log(r.data?.length ?? 0, r.error?.message ?? ""))
```

## 困ったとき

- **ログインすると「登録されていません」と出る**：手順4の `02_users.sql` を実行し直してください（手順3のアカウントを作ったあとに実行する必要があります）。
- **画面が「読み込み中…」のまま**：`app/config.js` の URL とキーを確認してください。
- **パスワードを忘れた**：`supabase/admin/relink_after_reset.sql` の先頭の手順で初期化します。
